1 | Costos

Grafos ponderados

En un grafo no ponderado, una arista indica que existe una conexión entre dos nodos. En muchos problemas reales no basta con saber que la conexión existe: también importa cuánto cuesta recorrerla.

Definición. Un grafo ponderado es un grafo en el que cada arista tiene asociado un valor numérico llamado peso.

Distancia

El peso puede representar kilómetros entre dos lugares.

Tiempo

Puede representar minutos de desplazamiento o latencia de red.

Costo

Puede representar dinero, energía o recursos consumidos.

Riesgo

Puede representar dificultad o exposición asociada a una decisión.

Pregunta clave. Ya no basta con preguntar cuántas aristas tiene el camino; también hay que preguntar cuál es el costo total.

2 | Camino

Costo de un camino

Un camino es una secuencia de nodos conectados por aristas. El costo de un camino se obtiene sumando los pesos de las aristas que lo componen.

CaminoPesosCosto total
A -> B -> D -> F4 + 5 + 615
A -> C -> E -> F2 + 10 + 315
A -> C -> B -> D -> F2 + 1 + 5 + 614
A -> C -> B -> D -> E -> F2 + 1 + 5 + 2 + 313
Idea clave. El camino con menos aristas no necesariamente es el camino de menor costo.

4 | Algoritmo

Dijkstra

El algoritmo de Dijkstra encuentra distancias mínimas desde un nodo origen hacia los demás nodos de un grafo con pesos no negativos. Para cada nodo mantiene la mejor distancia conocida y el predecesor que produjo esa mejora.

5 | Mejora

Relajación de una arista

Relajar una arista significa verificar si llegar a un nodo pasando por otro nodo produce una ruta más barata que la mejor conocida hasta ahora.

Regla. nuevo_costo = distancia[u] + peso(u,v). Si nuevo_costo < distancia[v], se actualiza distancia[v] y predecesor[v].
CasoCálculoResultado
Mejorar B pasando por Cdist(C) + peso(C,B) = 2 + 1 = 33 < 4, entonces B mejora.
Mejorar E pasando por Ddist(D) + peso(D,E) = 8 + 2 = 1010 < 12, entonces E mejora.
Mejorar F pasando por Edist(E) + peso(E,F) = 10 + 3 = 1313 < 14, entonces F mejora.

7 | Resultado

Reconstrucción del camino

La distancia mínima hasta F es 13. Para conocer la ruta se siguen los predecesores desde el objetivo hacia el origen y luego se lee la secuencia en sentido contrario.

Predecesores

F <- E, E <- D, D <- B, B <- C, C <- A

Camino mínimo

A -> C -> B -> D -> E -> F

Costo mínimo

2 + 1 + 5 + 2 + 3 = 13

Resultado

Llegar no es suficiente: se busca llegar con el menor costo posible.

8 | Condiciones

Pesos negativos y errores frecuentes

Dijkstra requiere pesos no negativos. Una arista negativa puede hacer que una ruta que parecía definitiva se vuelva más barata después.

Nodo finalizado

Cuando Dijkstra selecciona el nodo no visitado de menor distancia, su distancia queda definitiva bajo las condiciones del algoritmo.

Predecesor

El predecesor solo se actualiza cuando aparece una ruta de menor costo.

Costo acumulado

No se suma únicamente la última arista: se suma la distancia acumulada más el peso nuevo.

Pesos negativos

Para grafos con pesos negativos se usan otros algoritmos, como Bellman-Ford.

9 | Práctica

Procedimiento manual para Dijkstra

  1. Asigna 0 al nodo inicial.
  2. Asigna infinito a todos los demás nodos.
  3. Selecciona el nodo no finalizado con menor distancia.
  4. Revisa cada vecino conectado por una arista.
  5. Calcula distancia_actual + peso_de_la_arista.
  6. Si el nuevo costo es menor, actualiza distancia y predecesor.
  7. Finaliza el nodo actual.
  8. Repite hasta llegar al objetivo o finalizar todos los nodos alcanzables.
  9. Reconstruye el camino usando los predecesores.

10 | Síntesis

Ideas clave

  • Un grafo ponderado asigna costos a sus aristas.
  • Un camino se evalúa sumando sus pesos.
  • Menos pasos no significa necesariamente menor costo.
  • Dijkstra mantiene la mejor distancia conocida hacia cada nodo.
  • La relajación intenta mejorar una distancia existente.
  • Los predecesores permiten reconstruir el camino mínimo.
  • Dijkstra requiere pesos no negativos.
Frase resumen. Dijkstra no busca llegar primero; busca llegar con el menor costo acumulado.

1 | Costs

Weighted graphs

In an unweighted graph, an edge only says that a connection exists between two nodes. In many real problems, knowing that the connection exists is not enough: the cost of using it also matters.

Definition. A weighted graph is a graph where each edge has an associated numerical value called a weight.

Distance

A weight can represent kilometers between two places.

Time

It can represent travel minutes or network latency.

Cost

It can represent money, energy, or consumed resources.

Risk

It can represent difficulty or exposure associated with a decision.

Key question. It is no longer enough to ask how many edges a path has; we also need to ask its total cost.

2 | Path

Path cost

A path is a sequence of nodes connected by edges. The cost of a path is obtained by adding the weights of the edges that compose it.

PathWeightsTotal cost
A -> B -> D -> F4 + 5 + 615
A -> C -> E -> F2 + 10 + 315
A -> C -> B -> D -> F2 + 1 + 5 + 614
A -> C -> B -> D -> E -> F2 + 1 + 5 + 2 + 313
Key idea. The path with fewer edges is not necessarily the path with the lowest cost.

4 | Algorithm

Dijkstra

Dijkstra's algorithm finds minimum distances from one source node to the other nodes of a graph with non-negative weights. For each node, it keeps the best known distance and the predecessor that produced that improvement.

5 | Improvement

Edge relaxation

Relaxing an edge means checking whether reaching a node through another node produces a cheaper route than the best one known so far.

Rule. new_cost = distance[u] + weight(u,v). If new_cost < distance[v], update distance[v] and predecessor[v].
CaseCalculationResult
Improve B through Cdist(C) + weight(C,B) = 2 + 1 = 33 < 4, so B improves.
Improve E through Ddist(D) + weight(D,E) = 8 + 2 = 1010 < 12, so E improves.
Improve F through Edist(E) + weight(E,F) = 10 + 3 = 1313 < 14, so F improves.

7 | Result

Path reconstruction

The minimum distance to F is 13. To recover the route, follow the predecessors from the goal back to the source and then read the sequence in reverse order.

Predecessors

F <- E, E <- D, D <- B, B <- C, C <- A

Minimum path

A -> C -> B -> D -> E -> F

Minimum cost

2 + 1 + 5 + 2 + 3 = 13

Result

Reaching the goal is not enough: the goal is to arrive with the lowest possible cost.

8 | Conditions

Negative weights and common errors

Dijkstra requires non-negative weights. A negative edge can make a route that looked definitive become cheaper later.

Finalized node

When Dijkstra selects the unvisited node with the lowest distance, its distance becomes final under the algorithm conditions.

Predecessor

The predecessor is updated only when a lower-cost route appears.

Accumulated cost

Do not add only the last edge: add the accumulated distance plus the new weight.

Negative weights

Graphs with negative weights require other algorithms, such as Bellman-Ford.

9 | Practice

Manual procedure for Dijkstra

  1. Assign 0 to the initial node.
  2. Assign infinity to all other nodes.
  3. Select the unfinished node with the lowest distance.
  4. Check each neighbor connected by an edge.
  5. Compute current_distance + edge_weight.
  6. If the new cost is lower, update distance and predecessor.
  7. Finalize the current node.
  8. Repeat until the goal is reached or all reachable nodes are finalized.
  9. Reconstruct the path using predecessors.

10 | Synthesis

Key ideas

  • A weighted graph assigns costs to its edges.
  • A path is evaluated by adding its weights.
  • Fewer steps does not necessarily mean lower cost.
  • Dijkstra keeps the best known distance to each node.
  • Relaxation tries to improve an existing distance.
  • Predecessors make it possible to reconstruct the minimum path.
  • Dijkstra requires non-negative weights.
Summary phrase. Dijkstra does not try to arrive first; it tries to arrive with the lowest accumulated cost.
