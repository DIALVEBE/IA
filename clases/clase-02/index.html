1 | Representación

Búsqueda en grafos

En muchos problemas de inteligencia artificial es necesario encontrar una forma de llegar desde un estado inicial hasta un estado objetivo. Una manera natural de representar estos problemas es mediante grafos.

Definición. Un grafo se expresa como G = (V, E), donde V es el conjunto de vértices o nodos y E es el conjunto de aristas o conexiones entre nodos.
ComponenteEjemploInterpretación
Vértices V{A, B, C, D, E, F, G, H, I, J, K, L, M}Estados posibles del problema.
Aristas E(A,B), (A,C), (A,D), (B,E), (B,F), (F,J), (F,K), (K,M)Conexiones o transiciones entre estados.

2 | Formulación

Problema de búsqueda

Resolver un problema de búsqueda implica identificar el punto de partida, el estado que se desea encontrar y las alternativas disponibles en cada paso. En el grafo anterior, el problema puede formularse como encontrar una secuencia de nodos desde A hasta M.

Nodo inicial

Punto desde el cual comienza la búsqueda. En el ejemplo: A.

Nodo objetivo

Estado que se quiere encontrar. En el ejemplo: M.

Conexiones

Movimientos posibles entre estados.

Regla de selección

Criterio utilizado cuando existen varias alternativas.

3 | Estrategia

Depth-First Search

Depth-First Search, o búsqueda en profundidad, explora una rama del grafo tan profundamente como sea posible antes de regresar y explorar otra alternativa.

Regla de oro. DFS no salta: profundiza o retrocede.

4 | Selección

Regla de desempate

DFS indica que se debe profundizar, pero no determina por sí mismo cuál vecino seleccionar cuando existen varias opciones. Por eso se necesita una regla explícita.

La selección no ocurre porque un nodo esté dibujado a la izquierda, sino porque se definió una regla. En estos ejemplos se usa orden alfabético ascendente.

5 | Ejemplo resuelto

Encontrar M desde A

Con nodo inicial A, nodo objetivo M y orden alfabético ascendente, DFS explora una rama hasta no poder continuar. Después retrocede hasta el nodo más reciente con una alternativa pendiente.

PasoNodoDecisiónOrden acumulado
1AVecinos B, C, D. Se elige B.A
2BVecinos no visitados E, F. Se elige E.A -> B
3ENo hay vecinos nuevos. Se retrocede a B.A -> B -> E
4FEntre J y K, se elige J.A -> B -> E -> F
5JNo hay vecinos nuevos. Se retrocede a F.A -> B -> E -> F -> J
6KQueda M como vecino no visitado.A -> B -> E -> F -> J -> K
7MEl objetivo fue encontrado.A -> B -> E -> F -> J -> K -> M

6 | Distinción

Orden de exploración y camino solución

El orden de exploración y el camino solución no son equivalentes. El primero registra la secuencia en la que DFS descubre nodos; el segundo contiene solamente las conexiones que unen el inicio con el objetivo.

Orden de exploración

A -> B -> E -> F -> J -> K -> M

Camino solución

A -> B -> F -> K -> M

Cuidado. Encontrar nodos durante la exploración no significa que todos pertenezcan a la ruta final.

7 | Memoria del algoritmo

Pila, retroceso y visitados

DFS está relacionado con una pila o stack. Una pila sigue el principio LIFO: el último en entrar es el primero en salir. Esta estructura permite recordar el camino activo y regresar cuando una rama no puede continuar.

MomentoPila activaAcción
Inicio[A]Se visita el nodo inicial.
Profundización[A, B, E]E no tiene vecinos nuevos.
Retroceso[A, B]E sale de la pila.
Nueva rama[A, B, F, K, M]Se encuentra el objetivo.

En grafos también se mantiene un conjunto de nodos visitados. Si aparece de nuevo un nodo que ya fue visitado, no se explora otra vez. Esto evita repetir trabajo y quedar atrapados en ciclos.

Regla práctica. Un nodo ya visitado no se vuelve a explorar.

8 | Alcance

DFS y la ruta más corta

DFS puede encontrar una solución, pero no garantiza encontrar la ruta más corta. Su estrategia consiste en profundizar primero, no en optimizar la longitud del camino.

Idea clave. Encontrar una solución no significa necesariamente encontrar la mejor solución.

9 | Práctica

Procedimiento manual para DFS

  1. Identifica el nodo inicial.
  2. Identifica el nodo objetivo.
  3. Define la regla de desempate.
  4. Marca el nodo actual como visitado.
  5. Verifica si el nodo actual es el objetivo.
  6. Identifica vecinos no visitados.
  7. Aplica la regla de desempate si hay varias alternativas.
  8. Profundiza si existe un vecino disponible.
  9. Retrocede si no existen vecinos disponibles.
  10. No explores de nuevo nodos ya visitados.
  11. Detén la búsqueda cuando encuentres el objetivo.

1 | Representation

Search in graphs

Many artificial intelligence problems require finding a way to move from an initial state to a goal state. Graphs are a natural representation for this kind of problem.

Definition. A graph is expressed as G = (V, E), where V is the set of vertices or nodes and E is the set of edges or connections between nodes.
ComponentExampleInterpretation
Vertices V{A, B, C, D, E, F, G, H, I, J, K, L, M}Possible states of the problem.
Edges E(A,B), (A,C), (A,D), (B,E), (B,F), (F,J), (F,K), (K,M)Connections or transitions between states.

2 | Formulation

Search problem

Solving a search problem means identifying the starting point, the state to be found, and the available alternatives at each step. In the previous graph, the problem is to find a sequence of nodes from A to M.

Initial node

Point where the search begins. In the example: A.

Goal node

State we want to find. In the example: M.

Connections

Possible moves between states.

Selection rule

Criterion used when there are several alternatives.

3 | Strategy

Depth-First Search

Depth-First Search explores one branch of a graph as deeply as possible before returning and exploring another alternative.

Golden rule. DFS does not jump: it goes deeper or backtracks.

4 | Selection

Tie-break rule

DFS says that the search should go deeper, but it does not decide by itself which neighbor to choose when several options exist. An explicit rule is required.

The selection does not happen because a node is drawn on the left; it happens because a rule was defined. These examples use ascending alphabetical order.

5 | Solved example

Find M from A

With initial node A, goal node M, and ascending alphabetical order, DFS explores a branch until it cannot continue. Then it backtracks to the most recent node with a pending alternative.

StepNodeDecisionAccumulated order
1ANeighbors B, C, D. Choose B.A
2BUnvisited neighbors E, F. Choose E.A -> B
3ENo new neighbors. Backtrack to B.A -> B -> E
4FBetween J and K, choose J.A -> B -> E -> F
5JNo new neighbors. Backtrack to F.A -> B -> E -> F -> J
6KM remains as an unvisited neighbor.A -> B -> E -> F -> J -> K
7MThe goal was found.A -> B -> E -> F -> J -> K -> M

6 | Distinction

Exploration order and solution path

The exploration order and the solution path are not equivalent. The first records the sequence in which DFS discovers nodes; the second contains only the connections that join the start node to the goal.

Exploration order

A -> B -> E -> F -> J -> K -> M

Solution path

A -> B -> F -> K -> M

Careful. Finding nodes during exploration does not mean that all of them belong to the final route.

7 | Algorithm memory

Stack, backtracking, and visited nodes

DFS is related to a stack. A stack follows the LIFO principle: last in, first out. This structure remembers the active path and makes it possible to return when a branch cannot continue.

MomentActive stackAction
Start[A]Visit the initial node.
Go deeper[A, B, E]E has no new neighbors.
Backtrack[A, B]E leaves the stack.
New branch[A, B, F, K, M]The goal is found.

In graphs, DFS also keeps a set of visited nodes. If a node appears again after it was already visited, it should not be explored again. This avoids repeated work and prevents cycles from trapping the search.

Practical rule. A visited node is not explored again.

8 | Scope

DFS and the shortest path

DFS can find a solution, but it does not guarantee the shortest route. Its strategy is to go deeper first, not to optimize path length.

Key idea. Finding a solution does not necessarily mean finding the best solution.

9 | Practice

Manual procedure for DFS

  1. Identify the initial node.
  2. Identify the goal node.
  3. Define the tie-break rule.
  4. Mark the current node as visited.
  5. Check whether the current node is the goal.
  6. Identify unvisited neighbors.
  7. Apply the tie-break rule if several alternatives exist.
  8. Go deeper if an available neighbor exists.
  9. Backtrack if no available neighbors exist.
  10. Do not explore visited nodes again.
  11. Stop the search when the goal is found.

10 | Synthesis

Key ideas

  • A graph represents possible states and connections.
  • DFS explores depth first.
  • When it cannot continue, it backtracks.
  • The successor order changes the traversal.
  • Graphs require controlling visited nodes.
  • The exploration order is not necessarily the solution path.
  • DFS can find a solution without finding the shortest one.
Summary phrase. DFS does not jump: it goes deeper or backtracks.
